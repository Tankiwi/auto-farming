# 2026-10-19：底盘单通道 PWM 与编码器测试

## 前提与实现

用户指定 SSH `jetson@10.253.197.6`，确认测试条件。测试时 agent 将选项答复理解为四轮稳固悬空；用户随后明确更正“小车放在空旷的地面上”，故本次实际为地面测试，此更正取代此前的悬空环境记录。实测主机 `yahboom`，Ubuntu 22.04.5 LTS；`/dev/myserial -> /dev/ttyUSB2`，115200，测试前后未发现串口占用者。固件版本应答 `[3, 5]`，静止时四路编码器持续上报。

地面上车身移动可能带动未主动驱动的轮子，使其他编码器变化；因此本脚本按悬空设计的“非目标路不超过 3 计数”判据不适合直接验收本次地面单路测试。日志中的 failed 和数据保留为程序实际结果，不据此认定通道隔离故障；被动滚动是合理解释，实际轮位、车身位移与变化来源未独立核对。2～4 路仍未单独驱动，不能据此补记为全部通过。

通过 Python loader 读取设备实际安装的 `Rosmaster_Lib 3.3.1` 源码（安装包是 egg 文件，不能当普通目录读取）。核对 `set_motor` 为四个有符号 PWM 字节、功能码 `0x10`、长度 7，校验为 `(sum(fields)+5)&255`；编码器为 `0x0D`、四个小端有符号 32 位整数。直接收发已核对帧，未实例化会开启舵机扭矩的原厂对象，未经过 ROS/Docker，未修改车型、PID、上报配置、扭矩或 flash。

新增 [motor-check.py](../../modules/chassis/motor-check.py)，默认只查询版本、接收静止反馈。运动需显式 `--run --clear-confirmed`。串口要求无占用，并使用与机械臂脚本共用的文件锁。每个脉冲由独立子进程发送，计时后连续三次发送四路零 PWM，父进程负责接收；子进程脱离 SSH 会话，正常父进程退出不会取消已开始的定时归零。父进程清理时另发三次零 PWM。该机制不是硬件看门狗，不能覆盖整机死机、供电、USB/串口故障或子进程被强杀，也未实测这些故障。

测试判据：静止基线/脉冲前各路变化范围不超过 3 计数；目标路变化绝对值至少 5；非目标路变化绝对值不超过 3；末段约 0.4 秒至少五个编码器样本、各路范围不超过 3。正反向均完成后还检查目标路计数方向相反。这些是本轮检查阈值，不是标定精度或安全限位。

## 实测

数据为编码器原始计数，不能换算轮速或距离；实际轮位尚未对应。

| 轮次 | 指令（其余输出为零） | 持续 | 四路编码器变化 | 结果 |
|---|---|---|---|---|
| 初测 | 1 路 +15 PWM | 0.5 s | `[0, 0, 0, 0]` | 无明显反馈运动，终止；用户确认有轻微抖动/嗡鸣、未转起来 |
| 二测 | 1 路 +25 PWM | 0.5 s | `[-13, 0, 0, 0]` | 该步反馈判据通过 |
| 二测 | 1 路 -25 PWM | 0.5 s | `[29, 0, 0, 5]` | 4 路变化超过阈值，整轮终止，未测 2～4 路 |
| 用户要求增幅后 | 1 路 +35 PWM | 1 s | `[-452, -206, 1, -2]` | 2 路明显变化，整轮终止；未执行反向或 2～4 路 |

用户在增幅后确认“是的动了，一切正常”，可作为看到了动作、现场无异常的确认；未说明具体转动轮位或轮数，不能据此消除跨通道反馈疑点。不能把“编码器 2 变化”直接写成“2 号车轮被电气驱动”，也不能仅凭此认定接线错误或硬件故障。

各步末段 `stop_span` 均为 `[0,0,0,0]`。最后额外只读 1 秒，24 个有效编码器样本均为 `[-446,-195,-282,13]`，校验错误为零；最终串口无占用。较早的静止电压反馈为 10.8 V，只是板载读数，未校准、未测带载跌落，不据此认定电池故障或正常。

轮次之间，未指令通道也曾出现累计值变化：二测结束为 `[6,-4,-321,1]`，之后只读为 `[6,10,-321,0]`；三测基线为 `[6,11,-283,15]`。这些间隔未持续记录，是否有人工碰轮、支架变化、反馈或控制因素待核对，不归因为某一原因。
