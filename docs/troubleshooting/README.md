# 故障排查

更新：2026-10-19｜依据：历史设备测试及用户整车前检日志；本次文档更新未连接设备。

## 常见问题

| 现象 | 历史判断与本次排查入口 |
|---|---|
| `roscore: command not found` | 历史原因是终端为 ROS 2 Humble、教程要求 ROS 1；再次遇到时先核对终端环境；使用[机械臂环境](../environment/software.md#机械臂课程使用-ros-1-noetic-容器)的 Noetic 容器入口 |
| `Unable to set target init` | 历史 SRDF 预设为 `int`；第 7 课先备份后修改，见[仿真复现](../guides/arm.md#课程仿真复现)，重建容器后复核补丁 |
| Python 反解目标规划失败 | 历史 `02_set_pose_plan.py` 有 x≈111 m；核对当前源码，历史练习用 C++ 版，不用不可达例子判断环境故障 |
| Python 示例似乎无输出 | 管道或 timeout 可能丢失缓冲输出，使用 `PYTHONUNBUFFERED=1`；仍以退出码、规划及反馈判断 |
| ROS 节点列表为空 | 历史测试结束时已关闭驱动；当前原因需先检查驱动进程、报错与[ROS 2 环境准备](../environment/software.md#每个-ros-终端的环境准备)环境，再决定是否启动，避免重复占用设备 |
| 雷达 A1 驱动超时 | 实物为 YDLIDAR TG30，按[传感器指南](../guides/sensors.md)核对设备并使用 YDLIDAR 命令 |
| `/dev/myserial` 消失 | 核对底盘数据线及 USB 枚举；拔插对照已证明此别名对应底盘 |
| 底盘查询无回应 | 2026-10-11 自定义固件时曾无应答；刷回后版本/位置/编码器已通。当前再遇到时先查串口、占用及版本，不能直接沿用旧根因 |
| 车型参数 x3plus 被拒绝 | 原厂统一启动文件无 Plus 分支；环境标识已改，驱动未适配 |
| `Board mismatch ... car_type=1` | 底板保存配置与示例预期 2 不同，动作计划未发送；Python 对象的 car_type=2 不自动改底板。按[独立配置流程](../guides/chassis.md#显式设置-x3-plus-车型)处理，保存读回；目前尚无成功配置日志 |
| 退出时接收线程报 fd 为 None | 旧示例关闭串口时原厂无限接收线程仍在读取。本地已加可结束会话、先等线程退出再关串口；用户第二次修复版日志无此异常。不要因此判断板卡损坏或删掉车型检查，见[报告](../reports/2026-10-19-motion-demo-preflight.md) |
| 地面单轮测试其他编码器变化 | 车身可能带动未驱动轮子，悬空隔离判据不适用于直接判定地面故障；不等于其余电机独立驱动已通过，见[现场条件更正](../reports/2026-10-19-motor-test.md) |
| 缺少 `set_X3Plus.sh` | 2026-10-11 未发现该教程路径，当前存在性需复核，不能声称已运行官方切换脚本 |
| 相机有警告但图像正常 | 当时存在插件重复注册等提示；以持续消息与图像质量为依据，警告根因未修复 |
| RDP 连不上 | 端口监听不等于认证成功；按[远程连接](../guides/remote-access.md)核对当前 IP、桌面服务及 RDP 凭据 |
| 磁盘空间不足 | 停止录制并核对文件大小，由团队决定迁移哪些数据；不自动删除原厂资料 |

官方说明书称出厂固件已烧录，但本项目后来刷过底板程序，不能据此推断当前仍是原厂固件。现阶段无硬件损坏结论，也没有刷写必要性的充分证据。
