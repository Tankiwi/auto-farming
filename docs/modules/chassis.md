# 底盘与自定义固件

更新：2026-10-19｜证据：历史测试、2026-10-18 舵机测试及 2026-10-19 底盘单路 PWM 实测。

本目录尚无固件、板卡设计或 ROS 底盘驱动源码。2026-10-11 用户确认曾刷写自定义底板程序；版本和协议未知。USB 映射通过，原厂协议查询无应答。该结果未证明硬件损坏或固件兼容性根因，按既有团队决定暂缓排查。

2026-10-18 用户表示“底板刷回来了”，按刷回原厂固件的情况继续排查；随后经 `/dev/myserial`、115200 查询读到版本字节 `03 05`（库格式为 `3.5`），六个舵机位置有应答，6 号小幅动作用户确认正常，精确返回未通过。详见[实测记录](../reports/2026-10-18-arm-servo-test.md)。具体固件文件和板卡版本仍待归档，底盘运动与停车未测试。上述新证据取代“当前自定义固件／原厂协议未通”的状态，不改写历史失败结果。

2026-10-19 单路测试中，1 路 ±25 PWM 有编码器变化；增至 +35 PWM、1 秒后用户确认看到正常动作，非指令的 2 路同时变化 -206 计数，程序按悬空隔离判据归零并终止。用户随后更正实际为地面测试，其他轮子可能被动滚动，不能据此认定通道故障。末次 1 秒只读反馈静止；2～4 路未独立测试，整车可控行驶、急停与断线停车未验收。此项取代“底盘从未测试”的当前状态，详见[实测报告](../reports/2026-10-19-motor-test.md)、[操作指南](../guides/chassis.md)与本地 [motor-check.py](../../modules/chassis/motor-check.py)。

操作前参考[硬件环境](../environment/hardware.md)、[软件环境](../environment/software.md)和[故障排查](../troubleshooting/README.md)。证据见[历史测试](../reports/2026-10-11-static-tests.md)，跨模块接口见[架构地图](../architecture.md)。

## 底盘接入恢复时的交接资料

编程前先查[官方 Python 运动 API 清单](../references/rosmaster-motion-api.md)：已核对本机安装源码的全部 38 个公开方法，含三类底盘控制、停止形式、反馈、车型/PID 配置及跨车型限制；接口存在不等于本机已验收。

简单整车动作示例：[motion-demo.py](../../modules/chassis/motion-demo.py)，默认预览，显式开关才请求前后移动及左右旋转；[参数、上传和停止边界](../guides/chassis.md#官方速度接口动作示例本地准备未部署未真机执行)。用户随后上传并执行旧版，读回固件 3.5、底板车型 1，被车型检查拒绝，非零计划未执行；[本地修复退出竞争](../reports/2026-10-19-motion-demo-preflight.md)后尚未重新部署。底板车型未更改，整车运动验收不扩大。

恢复底盘开发前，归档自定义固件源码、二进制、版本、目标板卡和烧录步骤，并确认：

1. 通信端口、波特率、数据位、校验位和停止位。
2. 帧头、长度、命令码、校验算法及请求／响应示例。
3. 速度指令的单位、坐标方向、速度限制及停车／通信超时行为。
4. 编码器、底盘速度、IMU、电压反馈的字段和频率。
5. 机械臂是否由同一固件控制，舵机编号、限位及启动行为。

接入顺序：只读反馈 → ROS 2 消息发布 → 底盘坐标与里程计 → 受控低速和停止验证 → 建图定位 → 导航。整车模型、传感器安装外参和机械臂适配应使用 X3 Plus 的实物信息，不能直接沿用 X3 参数。
